이번 자료는 이 플러그인이 미팅 전후에 무엇을 읽고 쓰는지,
그리고 어떤 결정이 GOAL.md를 바꾸는지 이해하는 것이 목적이다. This material explains what the plugin reads and writes around a meeting,
and which decisions change GOAL.md.

  • 질문 1. 다섯 단계(목표 작성, 자료 준비, 미팅, 노트 작성, 발표 자료 작성)는 어떤 순서로 어떤 파일을 읽고 쓰는가Q1. In what order do the five steps (set goal, prepare slides, meeting, write note, presentation) read and write which files?
  • 질문 2. 미팅에서 나온 것 중 GOAL.md를 바꾸는 것과 바꾸지 않는 것은 무엇인가Q2. Which outcomes of a meeting change GOAL.md, and which do not?

drive-project-forward의 미팅 주기 전체 구조 (스킬 3개, 다음 단계가 읽는 기록 2개) Full meeting cycle of drive-project-forward (3 skills, 2 records read by later steps)

미팅 노트가 다음 미팅 자료의 리마인드가 되어 미팅이 한 주기로 이어지고,
GOAL.md는 주기 밖의 기준으로 읽히다가 사용자가 목표를 조정할 때만 바뀐다. The note becomes the reminder in the next meeting's slides, closing the cycle;
GOAL.md sits outside it as the reference and changes only when the user adjusts the goal.

질문 2 · 동작 설명Q2 · How it works

노트 작성(④)에서 결정 종류별로 기록하는 위치 Where writing the note (④) records each kind of meeting outcome

방법이나 구현을 바꾸는 결정은 미팅 노트에만 남고, GOAL.md는 사용자가 목표 자체를 조정할 때만 바뀐다. Decisions that change the method or code stay in the note;
GOAL.md changes only when the user adjusts the goal itself.
